# OpenMiniPaints — Paint Catalog API v1

## 1. Problem

There is no freely accessible, machine-readable catalog of miniature paint ranges. Every app that wants to offer paint lookup (barcode scanning, code search, autocomplete) has to either scrape unreliable sources, hardcode a small static list, or build the data from scratch.

PaintTrackerLAH currently ships ~30 hardcoded paints. At that size, the Quick Add and catalog search features feel token. The broader miniature painting community — hobbyists building apps, spreadsheet tools, community sites — has the same problem.

A clean, open catalog API would serve everyone, and could generate revenue through metered API access once it reaches useful coverage.

Hex color data is the most valuable field in the catalog — it enables colour-chip previews, palette building, and nearest-neighbour search. Manufacturers do not expose hex values via any public API; they exist only in product imagery. The catalog must derive hex values from paint swatch images.

---

## 2. Solution

Build OpenMiniPaints: a REST API backed by a curated Convex database covering six major miniature paint brands. The catalog is populated via a three-phase data pipeline: scrape (metadata + image URLs per brand), enrich (Claude Vision extracts hex colors from downloaded images), and import (curated JSON pushed to Convex). The API is served via Convex HTTP actions. Consumers authenticate with API keys. PaintTrackerLAH becomes the first consumer. The data model and API contract are kept stable from v1 so consumers can build on it.

## 4. Architecture

### Component structure

```
convex/
  schema.ts               # catalogPaints table + apiKeys table
  catalog.ts              # HTTP actions: search, list, lookup, brands
  admin.ts                # internal mutations: upsertPaint, bulkImport
  apiKeys.ts              # internal query: getByHash
  http.ts                 # router
  _generated/             # auto-generated by Convex CLI

scripts/
  scrape/
    _common.ts            # shared Paint type (includes imageUrl), tryFetch, writeScraped
    citadel.ts            # scrape Citadel — metadata + imageUrl
    vallejo.ts            # scrape Vallejo Model Color — metadata + imageUrl
    ak-interactive.ts     # scrape AK 3rd Gen — metadata + imageUrl
    kimera.ts             # scrape Kimera — metadata + imageUrl
    proacryl.ts           # scrape ProAcryl — metadata + imageUrl
    army-painter.ts       # scrape Army Painter — metadata + imageUrl (Shopify API)
    all.ts                # run all scrapers sequentially
  enrich/
    _vision.ts            # Claude Vision helper: image buffer → hex string
    hex-extractor.ts      # reads scraped JSON → downloads images → enriches → curated JSON
  import.ts               # reads curated JSON → calls admin.bulkImport
  generate-key.ts         # creates an API key in Convex

data/
  scraped/                # raw JSON from scrape scripts (gitignored)
  images/                 # downloaded paint images, keyed by brand/name (gitignored)
  curated/                # enriched JSON ready for import (committed)

.prd/
  prd-v1.md               # this file

package.json
.env.local                # CONVEX_DEPLOYMENT, CONVEX_URL, ANTHROPIC_API_KEY (gitignored)
README.md
```

### Key components

**`convex/schema.ts`** — defines two tables:
- `catalogPaints` — one row per paint: brand, name, paintType, hexColor, brandCode, barcode, transparency, finish, specialType; search index on `name` + `brand`
- `apiKeys` — keyHash, label, createdAt, revokedAt

**`convex/catalog.ts` (HTTP actions)** — four endpoints, API key required:
- `GET /search?q=&brand=` — full-text search via Convex search index, results grouped by brand
- `GET /brands` — list all brands with paint counts
- `GET /paints?brand=&type=&cursor=` — list paints with filters, paginated
- `GET /lookup?code=&barcode=` — exact match by brandCode or barcode

**`convex/admin.ts`** — internal mutations only (not HTTP-exposed):
- `upsertPaint` — insert or update a single paint by brand + name
- `bulkImport` — accepts an array, upserts each, returns `{ inserted, updated, errors }`

**Scrape scripts** — one per brand:
- Attempt live fetch from brand source; fall back to seed sample on failure
- Capture `imageUrl` alongside paint metadata wherever the source provides it
- Army Painter uses Shopify `/collections/.../products.json` — `images[0].src` is the image URL
- Other brands: extract product image URL from HTML response where parseable; omit if unavailable
- Exit with code 0 on success, 1 on complete failure
- Print per-brand summary: paints written, source (`live`/`seed`), count with imageUrl, count with hexColor

**`scripts/enrich/_vision.ts`** — Claude Vision helper:
- Accepts local image path + paint context (name, brand)
- Encodes image as base64, sends to `claude-sonnet-4-6` via `@anthropic-ai/sdk`
- Prompt: *"This is a product image of '[name]' by [brand]. Return only the dominant hex color of the paint swatch in the format #RRGGBB. No explanation."*
- Retries up to 3× on rate limit; returns `string | null`

**`scripts/enrich/hex-extractor.ts`** — enrichment runner:
```
npx tsx scripts/enrich/hex-extractor.ts [--brand <slug>]
```
For each paint in `data/scraped/<brand>.json` that has an `imageUrl` but no `hexColor`:
1. Downloads image to `data/images/<brand>/<sanitized-name>.jpg` (skips if already cached)
2. Calls `_vision.ts` to extract hex
3. Writes enriched paint (with `hexColor`) to `data/curated/<brand>.json`
Paints with no imageUrl, or where vision returns null, retain their seed `hexColor` (or leave the field blank — no paint is dropped).

**`scripts/import.ts`** — reads from `data/curated/<brand>.json`, calls `bulkImport`. Prints per-brand summary.

**`scripts/generate-key.ts`** — creates a new API key record, prints the raw key once.

### Data flow

**Catalog search request:**
```
Consumer sends:
  GET /search?q=abaddon&brand=Citadel
  Header: x-api-key: <key>

catalog.ts HTTP action:
  1. Hash incoming key, look up in apiKeys table
  2. If not found or revoked → 401
  3. Run Convex search index on catalogPaints
  4. Group results by brand
  5. Return: { results: { Citadel: [...] }, total: N }
```

**Data pipeline — three phases, all per-brand isolated:**
```
Phase 1 — Scrape
  npx tsx scripts/scrape/army-painter.ts
  → data/scraped/army-painter.json
    { name, paintType, brandCode, barcode, imageUrl, ... }

Phase 2 — Enrich (hex extraction via Claude Vision)
  npx tsx scripts/enrich/hex-extractor.ts --brand army-painter
  → downloads images to data/images/army-painter/
  → calls Claude Vision per paint without hexColor
  → data/curated/army-painter.json
    { ...scraped fields, hexColor: "#a3b2c1" }

Phase 3 — Import
  npx tsx scripts/import.ts
  → reads data/curated/army-painter.json
  → calls admin.bulkImport
  → "Army Painter: 250 inserted, 0 updated, 0 errors"
```

**PaintTrackerLAH integration (post-v1):**
```
useCatalogSearch('abaddon') in PaintTrackerLAH
  → GET /search?q=abaddon on OpenMiniPaints API
  → API key from PAINT_CATALOG_API_KEY env var
  → renders grouped results in Quick Add modal

barcode scan in PaintQuickAdd
  → GET /lookup?barcode=5011921xxx
  → returns matching paint → auto-fills form
```

### Integration points

- `ANTHROPIC_API_KEY` env var required for the enrichment phase (local only; never deployed to Convex)
- PaintTrackerLAH `useCatalogSearch.ts` — today hits static array; swaps to `/search` endpoint
- PaintTrackerLAH `PaintQuickAdd.vue` barcode tab — today hits static array; swaps to `/lookup`
- Convex deployment URL (`<project>.convex.site`) becomes the API base URL — no Vercel needed for the API itself

## Dependencies & Risks

| Dependency / Risk | Impact | Mitigation |
|---|---|---|
| Scrape sources change structure | Script breaks, data gaps | Scripts are isolated per brand — fix one without touching others |
| Manufacturer product images unavailable or non-standard | Low hex coverage | Seed hexColor values kept as fallback; vision coverage reported per run |
| Claude Vision returns wrong hex | Inaccurate colour data | Output is reviewable in curated JSON before import; can re-run per brand |
| Anthropic API rate limits during bulk enrichment | Slow enrichment runs | Retry logic in `_vision.ts`; image cache means partial runs are resumable |
| Convex search index limitations | Less powerful than Elasticsearch | Sufficient for v1; Typesense upgrade path in v2 |
| Legal: scraping manufacturer sites | ToS risk | Paint names and codes are factual, not copyrightable; review ToS per brand |

## Privacy & Security

- API keys stored as hashes — raw key shown once at generation time only
- All catalog data is factual (paint names, codes, colours) — no personal data
- No user data passes through this service in v1
- Invalid or missing key returns 401 with no data payload
- `ANTHROPIC_API_KEY` is a local-only secret used during the enrichment phase; it is never stored in Convex or committed to git
